# 0017. The C SDK: a pull transport the caller can replace, our own JSON reader, one arena per answer

Status: proposed, 2026-10-07

## Context

The platform's owner made C the next language on 2026-10-07, with C++ after it and Zig
on top of C later. C reaches what the other languages cannot: embedded and firmware
code, programs in languages that bind C (Zig, Nim, Odin, Lua, any FFI), and teams that
want one small static library and no runtime. Like every language here it is a
hand-written runtime plus the surface `iohr sdk generate` writes onto it (ADR 0011),
held to the same cases.

C gives none of what the other runtimes lean on: no HTTP client, no JSON, no threads on
every platform (C11 makes `<threads.h>` optional and macOS's libc has none), no
destructors, no generics, one global symbol namespace, and no package registry every C
programmer uses. Each of those is a decision below.

## Decision

| Language | Distribution | Include | Minimum | CI |
|---|---|---|---|---|
| C | source release `c/vX.Y.Z` (CMake, pkg-config); vcpkg and Conan later, with the owner | `#include <inorbithr/inorbithr.h>` | C11; CMake 3.20; libcurl 7.61.1 for the optional transport | Linux (gcc, clang) on pull requests; macOS (Apple clang) nightly and on release PRs; ASan and UBSan |

Names: every runtime symbol is `iohr_`, every constant `IOHR_`. Three libraries, each a
CMake target and a pkg-config module, in `c/`, the release-please component `c`:

| Library | Target, module | Holds | Depends on |
|---|---|---|---|
| `libinorbithr` | `inorbithr::inorbithr`, `inorbithr` | the runtime: client, tokens, retries, errors, JSON, pager, streams; no operation (ADR 0011) | libc; pthreads by default |
| `libinorbithr-api` | `inorbithr::api`, `inorbithr-api` | the public surface: every operation of `spec/openapi.json` (111 today) | `inorbithr` |
| `libinorbithr-curl` | `inorbithr::curl`, `inorbithr-curl` | the libcurl transport | `inorbithr`, libcurl |

A developer's own surface (`iohr sdk generate --lang c`) links `inorbithr` and not
`inorbithr-api`, and its symbols carry its own prefix (section 4), so the two never
define the same symbol.

### 1. HTTP: a pull transport the caller can replace; libcurl in its own library

The runtime defines `iohr_transport`, three functions and a context:

- `open(request)`: connect, send the request, read the status and headers;
- `read(response, buffer, wait)`: up to `buffer` bytes of the body, waiting at most
  `wait` milliseconds; zero bytes means the body ended, a timeout means nothing arrived;
- `close(response)`.

The runtime owns every clock: it passes `open` the time left of the attempt, and calls
`read` in slices of at most 100 ms, so it checks the cancel flag, the attempt timeout,
the total timeout and a stream's idle timeout itself, whatever transport sits below.
Pull rather than push because a stream and a pager are then the same loop, a C++
iterator, a Zig `next()` or a Lua coroutine can wrap either without a thread, and a push
transport is a loop over a pull one but not the other way around.

- **Why not libcurl in the core.** libcurl is the right default and nearly every Linux
  and macOS machine has it, but an embedded target has its own TCP and TLS stack (lwIP
  with mbedTLS, an RTOS socket API) and a Zig program has `std.http.Client`. A hard
  libcurl dependency would shut both out.
- **What a transport must do.** Never follow a redirect; verify every `https`
  certificate and fail when it cannot [SR-01, SR-02]; use no proxy the runtime did not
  name; speak only `http` and `https`. The conformance driver takes any transport, so a
  transport's author runs the cases against theirs; SR-19's bounds hold for a transport
  that passes them.
- **The curl transport.** `curl_multi` over one easy handle per call, taken from a pool
  under a mutex so connections are reused; `read` drives `curl_multi_wait` and pauses
  the transfer while the runtime's buffer is full. `CURLOPT_NOSIGNAL`, TLS 1.2 minimum,
  verification always on, no redirects, protocols limited to http and https, and the
  proxy always set explicitly (`CURLOPT_PROXY` and `CURLOPT_NOPROXY` from the runtime's
  own resolution, empty for none), so curl's own reading of `HTTPS_PROXY` never routes a
  call. Minimum libcurl 7.61.1 (RHEL 8; Ubuntu 22.04 has 7.81). `curl_global_init`
  runs inside `iohr_curl_transport_new` only when libcurl reports
  `CURL_VERSION_THREADSAFE` (7.84 and later); otherwise the program calls
  `iohr_curl_global_init()` once at start, as curl's rules require, and the README says so.

### 2. JSON: our own reader and writer, fuzzed, no vendored parser

The runtime has a strict RFC 8259 reader into an arena (about 700 lines) and a writer
into a growing buffer, which the runtime and generated code reach only through the
runtime's own `iohr_json_*` functions, so the parser can be replaced without touching a
surface.

- **The candidates.** cJSON (MIT, about 3,300 lines) sets its allocator through
  `cJSON_InitHooks`, one process-wide setting, which conflicts with a per-client
  allocator, and has had three NULL-dereference CVEs since 2023 (CVE-2023-50471,
  CVE-2023-50472, CVE-2024-31755). jsmn (MIT) is a tokenizer: no unescaping, no UTF-8
  checks, lenient by default, last released in 2019. yyjson (MIT) is excellent, fuzzed
  in OSS-Fuzz and takes an allocator per document, but its two source files are 756 KB
  at 0.13.0 (2026-09-08), larger than our runtime and surface together.
- **What ours does.** Rejects what RFC 8259 rejects (trailing commas, comments, leading
  zeros, lone surrogates, invalid UTF-8, control characters in strings), caps depth at
  64 and input at the 16 MiB answer cap, keeps numbers as their text (a 64-bit integer
  travels as a string anyway; the field that reads a number converts it), and keeps a
  string's length so an embedded `\u0000` survives. The writer refuses a caller's string
  that is not UTF-8 with `IOHR_E_INVALID`. It is checked against every `y_` and `n_`
  file of JSONTestSuite (pinned by commit, test data only) and fuzzed (section 6).
- **Trade-off.** We own a parser, a classic source of memory bugs. The controls are its
  size, the caps, the test suite, the sanitizers and continuous fuzzing. If it ever costs
  more than it saves, yyjson goes behind the same `iohr_json_*` functions, pinned by
  hash, and nothing generated changes.
- **TOML** for the M6 config file is not decided here: the PR that brings M6 to C picks
  between a small reader of our own and a vendored one (tomlc17, MIT), by the same
  rules.

### 3. Memory: one arena per answer, borrowed requests, the caller's allocator

- **Allocator hooks per client.** `iohr_allocator` holds `alloc`, `realloc` and `free`
  with a user pointer; the default is libc's. No global hooks, no global state: two
  clients may use two allocators (a Zig program passes its allocator).
- **An answer is one allocation tree with one owner.** Every value the SDK returns (an
  answer's model, a pager, a stream, an error) is a root; every string, list and nested
  model it reaches lives in the root's arena. The caller frees the root with one call,
  a typed `iohr_<model>_free(value)` (generated) or `iohr_free(value)`, and never
  anything inside it. A root carries a magic tag that the free checks first: freeing a
  pointer that is not a root aborts with a message instead of corrupting the heap. An
  item a pager yields and an event a stream yields are not roots: they belong to the
  pager or the stream and live until its next `_next` or its free.
  `iohr_meta_of(value)` gives the raw answer beside the typed one: status, headers, the
  client's and the server's request ids, the body [SR-17].
- **A request is borrowed.** Path parameters, query structs and bodies are the caller's;
  the SDK reads them during the call and keeps nothing after it returns. A pager borrows
  its parameters until it is freed.
- **Secrets.** The key secret and tokens live in buffers the runtime wipes before it
  frees them, with a wipe the compiler may not elide [SR-10, SR-11]. No error message,
  `to_json` output or log line contains them.

### 4. Shapes the surface generates

- **Prefixes.** The public surface in `inorbithr-api` uses `iohr_` (`iohr_me`,
  `iohr_radar_list_digests`, `iohr_digest`). A developer's surface uses `--package` as
  its prefix (`acme_`), by default the output directory's name, and refuses `iohr`.
- `iohr_str` is `{ const char *ptr; size_t len; }`: an explicit length, and `ptr`
  NUL-terminated in every answer so `printf("%s")` works; `ptr == NULL` is unset. A
  caller builds one with `iohr_s("...")`, a function.
- A required answer field is a plain value; an optional scalar has a `has_<name>` flag
  beside it; an optional string or model is `NULL` when unset. A request leaves out what
  is unset (design.md section 12). Unset timestamps are `""` on the wire, and
  `iohr_parse_timestamp` reads one into seconds and nanoseconds, `""` as no value.
- A list is `<name>` plus `<name>_len`; a string map is a list of `{key, value}` pairs.
  Enumerations stay `iohr_str`, so an unknown value survives (as in Go). A union and an
  untyped value are their raw JSON text (`iohr_json`, as Go's `json.RawMessage`).
- 64-bit integers are `int64_t` in C and decimal strings on the wire; the generated
  reader and writer convert, nowhere else.
- **Structs can grow.** Every struct a caller fills (a model, a parameter struct, the
  call options) starts with `size_t struct_size`, set by its `_init` function; the
  runtime reads only the fields inside that size, so a program compiled against an older
  header sends the newer fields as unset, and adding a field stays a minor change
  (design.md section 10). A struct with `struct_size == 0` is refused with
  `IOHR_E_INVALID` ("call iohr_x_init"). Structs the SDK allocates grow at the end.
  The client's configuration is opaque (`iohr_config`, built with setters), so it grows
  freely too.
- Every model has `_init`, `_free`, `_from_json` and `_to_json`.
- **Operations** are functions: `iohr_<tag>_<op>(client, path parameters..., params,
  body, options, &out, &err)`, flat ones `iohr_<op>` (`iohr_me`), each returning
  `iohr_status`.
- **Paging and streams are both pulled.** `iohr_<tag>_all_<op>` opens a pager and
  `iohr_<tag>_stream_events` opens a stream; `_next` gives the next item or event, or
  `NULL` at the end; `_free` stops and frees (a stream then closes its connection).
- **Profiles.** C has no generics, so a named profile is a distinct struct type
  (`acme_ci`, wrapping `iohr_client *`), and its operations take only that type: passing
  another profile's client is a constraint violation every C compiler must diagnose, an
  error under `-Werror`. The public surface is the public profile and takes
  `iohr_client *` itself.
- **The contract with the runtime.** `IOHR_CODEGEN_VERSION` is checked by every
  generated file with `#error`, and every operation also passes it to the runtime at run
  time, which refuses a surface built for another contract with `IOHR_E_CONFIG` (a
  shared library swapped under a compiled program).

### 5. Errors, threads, the platform

- **Errors are a status plus an optional object.** Every call returns `iohr_status`:
  `IOHR_OK`, then `IOHR_E_API`, `_CONNECTION`, `_TIMEOUT`, `_AUTH`, `_CONFIG`,
  `_INVALID`, `_CANCELLED`, `_DECODE`, `_TOO_LARGE`, `_NO_MEMORY`, `_NOT_IMPLEMENTED`
  (the kinds of design.md section 5, and C's own). The last argument, `iohr_error
  **err`, may be `NULL`; given, a failure fills it with a plain struct: the kind, the
  platform's `code` (the slugs of `spec/problem.json`, 18 today, as `iohr_code`, with
  `IOHR_CODE_UNKNOWN` keeping the raw slug), the HTTP status, the message, the typed
  details, both request ids. No per-thread or per-client "last error", so nothing races.
- **Threads.** A client is safe to share across threads: the token cache is guarded by
  a mutex, with single flight on a condition variable; everything else is per call.
- **The platform is a hook struct.** `iohr_platform` holds what the runtime needs from
  the system and C does not give: a mutex and a condition variable, entropy (jitter,
  request ids, idempotency keys), a monotonic clock and a sleep. The default is POSIX
  (pthreads, `getentropy` from POSIX.1-2024, which glibc 2.25 and macOS 10.12 have,
  `clock_gettime(CLOCK_MONOTONIC)`), and an RTOS or bare-metal program passes its own;
  `INORBITHR_THREADS=OFF` builds a runtime without pthreads whose client is for one
  thread. Windows is one more default (SRW locks, `BCryptGenRandom`), not a redesign.
- **Cancellation** is an opaque `iohr_cancel` (`_new`, `_set`, `_free`) named in the
  call options, set from any thread; the runtime checks it between read slices, so a
  blocked call ends within about 100 ms. No `_Atomic` appears in a public header, which
  keeps the headers usable from C++ before C++23 and from Zig's translate-c.
- **Behaviour** is what the cases define and every runtime does: the token exchange and
  refresh of design.md section 3, the retries, backoff with full jitter and
  `Retry-After` of section 6, one `x-request-id` and one `Idempotency-Key` per call
  reused on every attempt, the caller's `traceparent`, the 30 s attempt and 120 s total
  timeouts, the server-sent events rules and caps of section 7, `https` only except on
  loopback [SR-07].

### 6. Build, platforms, hardening

- **CMake** builds static and shared libraries and installs the headers, the CMake
  package config and the `.pc` files; `pkg-config --cflags --libs inorbithr-api
  inorbithr-curl` works for Make users. CI builds with `-Wall -Wextra -Wpedantic
  -Wconversion -Wshadow -Wstrict-prototypes -Werror`, C11 without extensions.
- **No single header.** The libraries are about 30,000 lines with the public surface;
  an stb-style header that big recompiles in every file that defines the
  implementation. A release can instead carry an amalgamation (`inorbithr.c` and
  `inorbithr.h`, as SQLite ships) for builds without CMake, such as Zig's build system
  or a firmware project. It is a later PR; nothing depends on it.
- **Platforms**, under ADR 0014: Linux with gcc and clang on every pull request that
  touches `c/`, the generator or the cases; macOS with Apple clang nightly and on
  release PRs. Windows is not built yet; the nightly lists it as a stated skip, and the
  README says so.
- **Sanitizers.** Unit tests and the conformance suite run under ASan and UBSan (clang,
  `-fno-sanitize-recover=all`) in the pull request cell.
- **Fuzzing.** libFuzzer targets for the JSON reader, the server-sent events parser, the
  error envelope and the generated readers of the most exposed answers (a page, an
  event), seeded from JSONTestSuite: a short run in the pull request cell, a longer one
  nightly.
- **Supply chain.** The only third-party code a user links is libcurl, from their
  system; the SBOM names it as an external dependency with the version range. FIPS
  [SR-08]: the SDK does no cryptography; the README says how to run libcurl on
  OpenSSL 3's FIPS provider.

### 7. Generation and conformance

- `iohr sdk generate --lang c` is a new target in `iohr-codegen` (`src/c/`), rendering
  from `ir` and `context` like Go and Java: a models header and source, an operations
  header and source, and a profiles header, golden-tested and compiled against the
  runtime with the wrong-profile check (`IOHR_TEST_COMPILE=c`). `mise run c:gen` writes
  the public surface into `c/api/generated/`; CI fails on a diff.
- `conformance:c` builds a driver in C that runs every case through the generated public
  surface, over the curl transport by default or any other one named at build time. The
  cases the first runtime cannot pass are `pending: [c]` with one parity issue in their
  notes, never weakened. The target is to pass more than Swift's first 29: the curl
  options make the TLS, mTLS and proxy cases cheap, so they are attempted in the same
  PR as the full surface; the M6 configuration file and credential chain, the
  middleware pipeline with logs and spans, the retry budget, rate limits and the
  `/v1/ws` socket stay pending until their own PRs.

### 8. Releases

The `c` component starts at `0.0.0` in the manifest; its first release-please PR
proposes the first version. Strict semver: before 1.0 a breaking change is a minor, a
`feat` or `fix` a patch (`docs/releasing.md`). The shared libraries' SONAME carries the
minor before 1.0 (`libinorbithr.so.0.N`) and the major after. A release is a tag and a
source archive with its SBOM and provenance; vcpkg and Conan ports wait for the owner,
like every first publication.

AGENTS.md says a runtime ships when it passes every case. So no `c` release PR is
merged while a case is `pending: [c]`, unless the owner records the exception in that
PR, as for any first release.

### 9. Zig, later, on top of this

The Zig package reimplements nothing: `zig/build.zig` compiles the C sources (or the
amalgamation) with Zig's own C compiler and translates the public headers with
`b.addTranslateC`, because Zig 0.16 deprecates `@cImport` in favour of the build
system's translate-c step. A thin layer turns `iohr_status` into error unions,
`iohr_str` into slices, pagers and streams into `next()` iterators, and a
`std.mem.Allocator` into the allocator hooks. The C API keeps that cheap:

- plain structs with explicit lengths; no flexible array members, bit-fields, anonymous
  unions or `_Atomic` in the public headers;
- every constant an `enum` or a `static const`, never only a macro, and every macro
  convenience also a function;
- callbacks with a `void *` context, no variadic functions;
- no `errno`, no thread-local state, no global initialisation in the core.

## Consequences

- `c` joins `pending` in `conformance/case.schema.json`, `Lang` in the command line,
  `tools/ci-changed.sh`, the CI workflow, the README's language table and
  `release-please-config.json`.
- The pull request that brings the runtime also brings its Linux CI cell with the
  sanitizers, JSONTestSuite and the generated-code diff, so no C code merges unchecked.
- The repository owns a JSON parser; fuzzing and JSONTestSuite are its price.
- A caller who builds without curl writes a transport, and the conformance driver is
  their test harness.
- `iohr sdk examples` gains C snippets in a later PR, once the docs site can show
  another language.
- Not in this ADR: C++ (its own ADR), Windows, the M6 pending set, the amalgamation,
  vcpkg and Conan.
