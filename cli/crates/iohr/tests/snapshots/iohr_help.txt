The InOrbit command line.

Sign in, keep several accounts as profiles, and call the API. A token is never an argument: pipe it
to `iohr login --with-token`, or set `IOHR_TOKEN`.

Usage: iohr [OPTIONS] <COMMAND>

Sign-in:
  login        Sign in and add a profile
  logout       Forget a profile and its credential on this machine
  whoami       Who the active profile is: subject, account, scopes, expiry
  profile      The profiles on this machine
  auth         Credentials for other programs: a profile's current access token
  token        API tokens for an account

Account:
  accounts     The accounts the credential can see
  domains      Domains an account controls, proved with one DNS record
  connectors   Browse the apps a connection can be made from
  connections  Manage the account's connections to outside systems
  config       Settings besides profiles: where extensions come from, which keys may sign them

Build:
  project      Create projects and manage project templates
  atlas        Keep the project's PRDs, RFCs, ADRs and studies in its atlas/ folder
  sync         Send the project's atlas documents to its Decisions space
  ext          Install, verify and run extensions
  sdk          Generate an SDK cut to what your credentials may call, and check it later
  api          Make one authenticated call and print the answer
  openapi      The OpenAPI document for this credential
  lab          Check lab documents kept in your repository
  decisions    Read and write RFCs, PRDs and ADRs in Decisions

Agents:
  ask          Ask your own AI agent a question in this folder
  shell        Shell integration: `? question` at your prompt asks your AI agent
  runner       Run coordinator turns on this machine
  coordinator  List and file the coordinator's jobs and asks
  memory       Keep what a project knows as files, check it, and sync it when you choose

Operate:
  tunnel       Open a loopback pipe to an environment's edge
  browser      Install the InOrbit Trails browser extension
  upgrade      Update iohr to the newest release
  completion   Print a shell completion script
  help         Print this message or the help of a command

Options:
  -h, --help
          Print help (see a summary with '-h')

  -V, --version
          Print version

Global options:
      --profile <PROFILE>
          The profile to use (default: the one `iohr profile use` chose)
          
          [env: IOHR_PROFILE=]

      --json
          Print JSON instead of tables

  -v, --verbose
          Describe each call on stderr: method, path, status, time, request id

      --env <NAME>
          The environment to call: `production` or `local`.
          
          Sets the API and sign-in addresses; `--base-url` and `IOHR_ISSUER` still win over it. The
          default is `production`.
          
          [env: IOHR_ENV=]

      --base-url <BASE_URL>
          The API's address (default: the environment's)
          
          [env: IOHR_BASE_URL=]

      --sign-in <WHO>
          Sign in as someone other than a person (`iohr runner` and `iohr coordinator` only).
          
          `io` is the `OAuth2` client `iohr-io` with the client credentials grant, so jobs Io files
          run on runners Io owns. `iohr runner` and `iohr coordinator` only; the secret is read from
          the file `IOHR_CLIENT_SECRET_FILE` names (mode 0600) or, on a Mac, from the keychain item
          the Mac bridge uses, never from an argument.

          Possible values:
          - io: Io, the `OAuth2` client `iohr-io` (client credentials)
          
          [env: IOHR_SIGN_IN=]

      --via-personality <NAME>
          With `--sign-in io`: the personality named in the `x-iohr-via` attribution header (RFC
          0065.2), such as `improver`. Attribution only, it grants nothing. Not `--via`, which `iohr
          ask` uses for where an answer comes from
          
          [env: IOHR_VIA_PERSONALITY=]

      --via-session <ID>
          With `--sign-in io`: the agent session named in `x-iohr-via`
          
          [env: IOHR_VIA_SESSION=]

      --via-job <ID>
          With `--sign-in io`: the coordinator job named in `x-iohr-via`
          
          [env: IOHR_VIA_JOB=]

Exit codes: 0 ok, 1 a finding or a failure, 2 usage, 3 not signed in, 4 forbidden.
